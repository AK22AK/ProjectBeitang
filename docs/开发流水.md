# 开发流水记录

## 2026-03-09

### 1. 修复 Cmd+N/M 崩溃问题
- **发现问题**：在使用 Cmd+N/M 呼出浮动输入窗口时，`gpui_component::input::Input` 组件试图读取其所在的全局 `Root` context 获取主题等配置，由于外层未被 `Root` 包裹，导致 `unwrap` panic 崩溃。
- **解决方案**：修改 `src/main.rs` 里的开窗逻辑，将单纯加载 `QuickAddWindow` 改为了外部包裹使用 `gpui_component::Root::new(view, window, cx).bg(...)` 进行渲染。

### 2. 修复快捷键优先级（!! / ！！）解析失效 Bug
- **发现问题**：通过快速输入小窗和主应用面板输入 `!! 高优先级` 或 `！普通优先级任务` 时，带有中文全角感叹号（`！`，`！！`）的前缀无法被代码识别，导致任务最终以“普通/低优先级”写入数据库。
- **解决方案**：在 `src/ui/floating_window.rs` 的 `parse_quick_input` 和 `src/ui/task_panel.rs` 的 `parse_input_static` 两个解析函数中，引入 `strip_prefix` 方法，同时匹配半角和全角的感叹号 (`!!`, `！！`, `!`, `！`) 进行识别和截断。
- **测试通过**：运行 `cargo test` 顺利通过全量测试集，保证了文本解析与 SQLite 持久化入库逻辑的完善。

## 2026-03-10

### 1. 任务面板新增记录删除功能
- **开发需求**：目前待办任务列表缺少移除任务的入口，当用户输错任务后无清理手段。
- **解决方案**：在 `src/ui/task_panel.rs` 中的 `TaskPanel` 组件新增 `delete_task` 异步方法，以连接后台 Store 的 `delete_record` 操作。并在单任务项呈现的 `render_task` UI 末尾处，追加了支持交互 Hover 的红色「✗」删除按钮，绑定了对应的点击事件。
- **验证结果**：任务在点击删除后顺利实现底层数据库与前端界面的同步清除体验闭环。

### 2. 修复已完成列表勾选失效并优化编辑体验
- **发现问题**：
  1. 点击位于底部的「已完成任务」项左侧的复选框，无法将其退回待办列表。经过排查发现是由于渲染循环使用了 `enumerate()`，导致底层与待办列表的 `.id(("checkbox", 0))` 发生了**组件 ID 冲突（ID Collision）**，使得事件监听失效。
  2. 原先的双击编辑体验（Double-click）在列表布局中容易与其他手势或文字选中产生冲突。
- **解决方案**：
  1. 修复 ID 冲突：在渲染已完成任务列表时，向元素的组件 ID 索引用了 `pending_count + idx` 进行递增偏移，确保当前视图内的所有组件 ID 全局唯一。
  2. 新增独立编辑按钮：取消双击事件，统一在列表（包括 TaskPanel 与 NotePanel）末尾、红色“✗”的左侧，新增了一个专属的蓝色编辑小图标（“✎”）。
- **优化产出**：不仅解决了复选框失效的问题，还对所有被废弃的 `use` 导出依赖（unused imports）进行了清理，达到「零 Warning 编译」。

### 3. 支持已完成任务区域的折叠与展开
- **开发需求**：已完成的任务如果不清理会越积越多，占用任务面板的空间。用户希望“已完成”区域可以折叠，并且默认就是折叠状态以保持界面清爽。
- **解决方案**：为 `TaskPanel` 的内部状态追加了 `show_completed: bool` 控制变量，默认值为 `false`。将“已完成”区域的纯文本标题改造为可点击交互的组件（赋予 `.id` 与 `.on_click` 事件以及视觉提示）。点击后会反转状态并调用 `cx.notify()` 实现视图重绘。
- **效果预览**：进入应用时自动折叠历史已完成记录，标题旁配备 `▶` / `▼` 箭头指示器，交互顺滑无警告。

### 4. 全局快捷键唤醒与防抢占焦点退出
- **开发需求**：用户希望在系统任意处按下 `Cmd+Shift+T` 都能弹出一个纯净的输入框供快速添加构思。完成后或者按 `<Esc>` 脱离时，当前电脑焦点要原封不动地交还给呼出前的应用，绝不能自作主张地弹出 Beitang 主界面强占工作流。
- **实施路径**：
  1. 系统驻留：基于 `global-hotkey` 的事件循环实现对 Cmd+Shift+T 底层组合键捕获，一旦捕捉就调用 `cx.open_window`。
  2. 开箱即用：利用 `InputState` 及 `cx.focus()` 在窗口实例化生命期的第一帧完成输入框对齐强制聚焦，彻底免去“召唤后还需手动点击一次白框”的累赘操作体验。
  3. 双向触发 (Toggle)：在应用的常驻循环中记录一份已展开浮层窗口的句柄 (`Option<AnyWindowHandle>`)，如检测按键再次下压而句柄还在，直接将窗口回收，表现得如同 Spotlight 一般。
  4. 顺滑回归工作状态：在首次快捷键激活期间利用 `cx.active_window().is_some()` 缓存此时应用是否有处于活跃期的其它窗口。将其存为 `hide_app_on_close` 封锁于关闭闭包（Esc与Enter事件中）。若应用被快捷键临时拉起，就在关闭窗口后附带触发 `cx.hide()`，让整个二进制应用从调度系统上主动“退缩”，此时 macOS 即会顺水推舟地将焦点交回你写到一半的代码编辑器上！
- **成果**：彻底打通了任意界面的“悬浮添加-销毁并恢复原状”这一极客功能核心闭环，并且继续消除了未使用依赖和多余空括号的编译器警告，巩固了 Rust 项目的高质量“0 Error, 0 Warning”洁癖式标准！

### 5. 解决快捷添加后主界面数据不同步的问题
- **发现问题**：通过快速输入屏（`QuickAddWindow`）向底层 SQLite 添加新产生的任务后，若此时切回应用主界面，发现该主界面上的 `TaskPanel` 与 `NotePanel` 的列表并未刷新，需要重启或通过操作再次触发刷新才能可见。这是因为在解耦的 Store 机制中，主面板错过了后台数据库刷新的有效感知。
- **实施路径**：
  鉴于用户习惯总是需要把主应用调用到前台来检查，我们通过对应用状态实现**侧窗口激活回调监听**来实现“自动感知更新”。利用 `cx.observe_window_activation()` 为数据面板组件（TaskPanel/NotePanel）注入了当所属主应用窗口从后台再次切换成为活跃前台 (`is_window_active() == true`) 时的事件订阅闭包，在切回瞬间重新发起 `load_tasks()` 与 `load_notes()` 数据库拉取，以最新的数据集重绘当前视图。
- **成果体验**：不仅彻底消除了数据视图滞后的生硬感，也完美避免了使用多余定时器轮询查库的资源浪费，只需“点回应用主舞台”，呈现的即是包含各种快捷小窗刚塞入最新数据后的完美同步列表。

### 6. 修复列表过长时的排版崩坏：滚动条消失与底部裁剪问题
- **发现问题**：
  1. **截断现象**：当“任务”与“笔记”列表项目太多时，向上滑不到底，底部直接被生硬地切掉。
  2. **滚动条消失现象**：初步尝试将外部容器设为随动的 `.flex_1()` 后，确实解决了截断，但带来了严重的副作用：列表的滚动条竟然整体“失联”罢工了，导致连拖拽滚动的功能一同瘫痪。
- **根本原因剖析（GPUI 级局限）**：
  在 GPUI 生态里 `overflow_y_scrollbar()` 滚动组件底层实现上，默认需将其包裹块判定为 `.size_full()` 以占满指定的绝对尺寸。如果直接把所在的 `div` 拆换成弹性占满的 `.flex_1()`，它无从获取高度确化继承值，会盲目认为自己的高度就是内部无限被撑开的内容高度。即：它觉得自己已经没多余被遮住的地方，干脆就把滚动条给吞掉了。
- **实施路径 (嵌套隔离法)**：
  1. **主页面盒子画定结界**：在 `src/main.rs` 的主展示区内容盒子上补充严格控制 `.flex_col().overflow_hidden()`，这道红线将永远强制内部膨胀出来的组件乖乖呆在整个屏幕的下方，多出部分必须通过拉滚动来展示。
  2. **剥离出专用的包装隔离盒**：在 `src/ui/task_panel.rs` 与 `src/ui/note_panel.rs` 中，用一个极具弹性的容器 `div().flex_1().overflow_hidden()` 作为代理层，它负责去“自满主界面内被分配的弹性余量”。
  3. **物尽其用**：将原本丢失滚动条的列表放置在上述代理层之内，恢复它自带的 `.size_full()` （此时它刚好占满了它上级那个固定的代理盒子），并加上准确的锚点标记 `.id("task-list")` / `.id("note-list")` 用以帮助系统级的组件逻辑确认最终下划的坐标位置。
- **成果体验**：不仅恢复了带滚动条视觉的标准状态，同时解决了 padding 顶着底部导致被切问题！现在的页面，就算里面塞了几十条待办项，拖动也依旧如牛油般顺滑且能妥妥碰到底端。
